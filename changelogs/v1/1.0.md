## [1.0.1-patch.1] - 2026-10-21

### Changed / 变更

- Changed the default permission level of `/warp create` (including `/warp add`) from `0` to `2`, matching `/warp del` and `/warp rename`. Explicit values in existing configurations remain unchanged; use `warp.create.permission.level` to adjust this setting.
  <br> `/warp create`（含 `/warp add`）的默认权限等级由 `0` 调整为 `2`，与 `/warp del`、`/warp rename` 保持一致。已有配置中的显式值不受影响，可通过 `warp.create.permission.level` 调整。

## [1.0.1] - 2026-10-21

### Added / 新增

- Bedrock Edition TPA request popups now show the request direction ("teleport to the other player" or "ask the other player to come") instead of only the sender's name.
  <br> 基岩版 TPA 请求弹窗现在会显示请求方向（“传送到对方”或“请求对方过来”），不再只显示发起者名称。
- Added expiration times for TPA requests, defaulting to 120 seconds, with separate configuration for `/tpa` and `/tpahere`.
  <br> TPA 请求新增过期时间，默认 120 秒；`/tpa` 与 `/tpahere` 可分别配置。
- Added `/tpay` and `/tpan` as all-lowercase aliases for `/tpaaccept` and `/tpadeny`.
  <br> 新增 `/tpay`、`/tpan` 作为 `/tpaaccept`、`/tpadeny` 对应的全小写写法。

### Changed / 变更

- Standardized the expiration field for `tpa.request` and `tpa.requestHere` in `config.json` as `expireSeconds`, defaulting to `120`; `0` disables expiration. Previously, TPA requests never expired in practice.
  <br> `config.json` 中 `tpa.request` 与 `tpa.requestHere` 的过期时间统一为 `expireSeconds` 字段，默认 `120`；`0` 表示永不过期。此前 TPA 请求实际永不过期。
- Only the `expireSeconds` fields under `tpa.request` and `tpa.requestHere` can be set through configuration commands; the field remains reserved in other nodes.
  <br> 只有 `tpa.request` 与 `tpa.requestHere` 的 `expireSeconds` 可通过配置命令设置，其余节点的该字段仍为预留。
- Added a "Bedrock TPA request popup" toggle to the main `/gtpa` interface to control whether incoming requests automatically open a form.
  <br> 基岩版 `/gtpa` 主界面新增“基岩版TPA请求弹窗”开关按钮，可直接切换收到请求时是否自动弹出表单。
- Made "Back" the first and default option in the player dropdown for Bedrock Edition outgoing-request forms; submitting it returns to the `/gtpa` main interface.
  <br> 基岩版发起请求表单的玩家下拉框第一位改为“返回”并作为默认选项，提交后回到 `/gtpa` 主界面。
- Changed the bottom button from "Back" to "Close" on automatically opened Bedrock Edition TPA request popups.
  <br> 基岩版收到 TPA 请求并自动打开弹窗时，底部按钮由“返回”改为“关闭”。
- Standardized TPA translations: `allow_request` now displays "Allow TPA Requests", and the popup toggle displays "Bedrock TPA Request Popup".
  <br> 统一调整 TPA 相关翻译：`allow_request` 状态显示为“允许TPA请求”，弹窗开关显示为“基岩版TPA请求弹窗”。

### Fixed / 修复

- Fixed "Back" in automatically opened Bedrock Edition TPA request popups opening the request list, which was not the parent interface.
  <br> 修复基岩版自动打开的 TPA 请求弹窗中“返回”会打开请求列表的问题，该列表并非当时所在的上一级界面。
- Fixed returning to the main interface after sending a request even when no valid target was selected.
  <br> 修复发起请求后即使未选择有效目标也会返回主界面的问题。
- Fixed incorrect author metadata formatting preventing the author list from appearing on NeoForge.
  <br> 修复 NeoForge 下作者信息格式错误导致作者列表不显示的问题。
- Corrected the organization name from `ZCT Stuido` to `ZCT Studio` and updated links in the license and mod metadata accordingly.
  <br> 修正组织名拼写 `ZCT Stuido` → `ZCT Studio`，同步更新许可证与模组元数据中的链接。

### Removed / 移除

- Removed item icons from Bedrock Edition forms and buttons, reverting to text-only buttons.
  <br> 移除基岩版表单与按钮上的物品图标（已回退），恢复为纯文本按钮。

## [1.0.1-rc2] - 2026-10-21

### Added / 新增

- Added `/randomtp` (`/rtp` alias) for random teleportation within the current dimension, searching for safe destinations between configurable minimum and maximum distances from the player. Supports cooldown, permission level, and distance settings.
  <br> 新增 `/randomtp` 随机传送命令（`/rtp` 为别名）：在当前维度内以玩家当前位置为中心，在配置的最小距离与最大距离之间随机寻找安全落点；支持冷却、权限等级、距离范围配置。
- Added a `commands` toggle section to `config.json`. All commands and aliases except the three root commands `teleportgui`, `teleportgui_admin`, and `teleportgui_be` can be disabled; disabled commands are removed from the command tree and restored when re-enabled.
  <br> `config.json` 新增 `commands` 命令开关，除 `teleportgui`、`teleportgui_admin`、`teleportgui_be` 三个根命令外所有命令（含别名）均可禁用；禁用后命令会从命令树中移除，启用后重新加入。
- Added `/teleportgui_admin command <command>` to inspect command-group status and `/teleportgui_admin command <command> <true/false>` to enable or disable commands. Changes automatically save the configuration, rebuild the command tree, and synchronize online players' command lists.
  <br> 新增 `/teleportgui_admin command <命令>` 查看命令组状态、`/teleportgui_admin command <命令> <true/false>` 启用或禁用，修改后会自动保存配置、重建命令树并同步在线玩家的命令列表。
- Added `/teleportgui_admin config <key>` to inspect any configuration value, including values inherited from `defaults`.
  <br> 新增 `/teleportgui_admin config <键>`，可在游戏内查看任意配置项的当前值（含从 `defaults` 继承的结果）。
- Added `/teleportgui_be notif_gui` to inspect and change the Bedrock Edition teleport request popup setting.
  <br> 新增 `/teleportgui_be notif_gui` 查询和设置基岩版传送请求弹窗开关。
- Added `/teleportgui allow_request` to inspect and change whether other players may send teleport requests.
  <br> 新增 `/teleportgui allow_request` 查询和设置是否允许其他玩家向自己发送传送请求。
- Added `/teleportgui_admin config notifGuiDefault true/false` to adjust the global `notifGuiDefault` setting.
  <br> 新增 `/teleportgui_admin config notifGuiDefault true/false`，可调整 `notifGuiDefault` 全局默认值。
- Added `/teleportgui_admin reload command` and `/teleportgui_admin reload config`: the former rebuilds the current command tree, while the latter reloads `config.json` before rebuilding it.
  <br> 新增 `/teleportgui_admin reload command` 与 `/teleportgui_admin reload config`：前者重建当前命令树，后者重新读取 `config.json` 后再重建。
- `/reload` now also reloads `config.json` and updates the command tree.
  <br> `/reload` 现在会同时重新加载 `config.json` 并更新命令树。
- Added `teleport.random` to `config.json`, supporting `minDistance`, `maxDistance`, `cooldownSeconds`, and `permission.level`.
  <br> `config.json` 新增 `teleport.random` 节点，可配置 `minDistance`、`maxDistance`、`cooldownSeconds` 与 `permission.level`。
- Added `zh_hk` (Traditional Chinese, Hong Kong) and `zh_tw` (Traditional Chinese, Taiwan) language files.
  <br> 新增 `zh_hk`（繁体中文·香港）与 `zh_tw`（繁体中文·台湾）语言文件。
- Added `runtimePersistence` to `settings.yml`, defaulting to `true`. When set to `false`, cooldowns and TPA requests are kept only in memory, and `runtime.json` is neither read nor written.
  <br> `settings.yml` 新增 `runtimePersistence` 选项，默认 `true`；设为 `false` 后冷却与 TPA 请求仅保存在内存中，完全不读取、不写入 `runtime.json`。

### Changed / 变更

- Upgraded the `config.json` schema version to 3; older configurations automatically receive and save missing fields such as `commands` and `teleport.random` when loaded.
  <br> `config.json` 配置版本升级到 3；旧配置在加载时会自动补齐 `commands`、`teleport.random` 等新字段并保存。
- Standardized the random teleport command toggle name as `randomtp` (previously `rtp`); the `/rtp` alias follows the same toggle.
  <br> 随机传送的命令开关统一命名为 `randomtp`（此前为 `rtp`），`/rtp` 别名跟随该开关一起启用或禁用。
- Split root commands into `/teleportgui` for players, `/teleportgui_admin` for administrators, and `/teleportgui_be` for Bedrock Edition settings. `/teleportgui_admin` is hidden from unauthorized players.
  <br> 命令根拆分为玩家命令 `/teleportgui`、管理员命令 `/teleportgui_admin` 与基岩版设置 `/teleportgui_be`；`/teleportgui_admin` 对无权限玩家不可见。
- Added an incoming-request toggle to the `/gtpa` interface (emerald block for enabled, redstone block for disabled), moved the request-list toggle to its right, and changed the home navigation button to "Close".
  <br> `/gtpa` 界面新增接收请求开关（绿宝石块开启、红石块关闭），原请求列表切换按钮移到其右侧；首页导航栏改为“关闭”。
- The TPA request list now uses actual player heads: an enchantment glint indicates a `/tpa` request, while no glint indicates `/tpahere`.
  <br> TPA 请求列表改用真正的玩家头颅：附魔光效表示 `/tpa` 请求，无光效表示 `/tpahere` 请求。
- Grouped command toggles by feature; aliases follow their primary command (for example, disabling `tpa` also removes `/tpahere`, `/tpaaccept`, `/gtpa`, and related commands).
  <br> 命令开关按功能分组，别名跟随主命令一起启用或禁用（例如禁用 `tpa` 会同时移除 `/tpahere`、`/tpaaccept`、`/gtpa` 等）。
- Optimized random teleportation by synchronously checking only loaded chunks, loading unloaded chunks asynchronously with at most four chunk attempts, and limiting downward scans to 48 blocks to avoid prolonged chunk generation on the server thread.
  <br> 优化随机传送：只同步检查已加载区块，未加载区块改为异步加载且最多尝试 4 个区块，下界扫描深度限制为 48 格，避免服务器线程连续生成区块造成卡顿。
- When `runtimePersistence=true`, cooldowns and pending TPA requests are stored in `teleportgui/runtime.json` and survive server restarts.
  <br> 当 `runtimePersistence=true` 时，冷却与待处理 TPA 请求写入 `teleportgui/runtime.json`，服务器重启后保留。
- The root commands `teleportgui`, `teleportgui_admin`, and `teleportgui_be` can never be disabled by command toggles, ensuring administrators can restore other commands.
  <br> `teleportgui`、`teleportgui_admin`、`teleportgui_be` 永远不会被命令开关禁用，确保管理员始终可以恢复其他命令。
- Changed the version number to `1.0.0-rc.2`.
  <br> 版本号变更为 `1.0.1-rc.2`。

### Removed / 移除

- Removed the SQLite storage backend; TeleportGUI now always uses JSON storage (`teleportgui/storage.json`).
  <br> 移除 SQLite 存储后端，TeleportGUI 现在始终使用 JSON 存储（`teleportgui/storage.json`）。
- Removed the reserved `logLevel`, `autoMigrate`, and `storage` / `storage.type` options from `settings.yml`. These legacy keys are ignored, and `settings.yml` now only retains `runtimePersistence`.
  <br> 移除 `settings.yml` 中的 `logLevel`、`autoMigrate` 与 `storage` / `storage.type` 预留配置；这些旧键会被忽略，`settings.yml` 现在只保留 `runtimePersistence`。
- Legacy `storage` / `storage.sqlite` settings in `settings.yml` are ignored; existing `storage.db` files are not migrated automatically.
  <br> 旧 `settings.yml` 中的 `storage` / `storage.sqlite` 配置会被忽略；已有 `storage.db` 不会自动迁移。

### Fixed / 修复

- Reworked the anvil interface for creating and renaming entries: the first slot shows the appropriate home/warp icon and name, and the second slot always means "Back". Fixed the default home name being set to "Back" when creating a home.
  <br> 重做创建/重命名铁砧界面：第一格按家/传送点显示对应图标与名称，第二格统一为“返回上一级”，修复创建家时默认名字被填成“返回上一级”的问题。
- Fixed warp deletion and renaming always requiring permission level 4. They now use `warp.del.permission.level` and `warp.rename.permission.level`, defaulting to level 2; GUI management buttons also follow configured permissions.
  <br> 修复传送点删除与重命名始终硬性要求权限等级 4 的问题。现在由 `warp.del.permission.level` 与 `warp.rename.permission.level` 控制，默认等级 2；GUI 管理按钮也按配置权限显示。
- Fixed server crashes caused by `NoClassDefFoundError: org/yaml/snakeyaml/Yaml` because SnakeYAML was missing from release builds. `settings.yml` now uses a built-in lightweight parser instead of a third-party YAML library.
  <br> 修复发布版未打包 SnakeYAML，导致服务器启动时因 `NoClassDefFoundError: org/yaml/snakeyaml/Yaml` 崩溃的问题。`settings.yml` 现在使用内置的轻量解析器，不再依赖第三方 YAML 库。
